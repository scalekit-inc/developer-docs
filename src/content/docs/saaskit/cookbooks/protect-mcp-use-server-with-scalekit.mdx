An [mcp-use](https://mcp-use.com) server over Streamable HTTP is one URL that many MCP hosts share: Inspector, Claude, Cursor, a teammate's agent. A shared API key on that URL authenticates *the server*, not *the caller*. Tools then see one identity for everyone.

Scalekit MCP Auth issues an OAuth 2.1 access token per sign-in. The mcp-use process verifies that JSON Web Token (JWT) against Scalekit's JSON Web Key Set (JWKS). Tools read `ctx.auth.user.id`. The resource server never holds a Scalekit client id or secret and does not use `@scalekit-sdk/node`.

## The problem

- **One URL, many people.** A shared secret cannot scope documents, todos, or mail to the person who signed in.
- **A copied verifier drifts.** Dual issuer values, `aud = res_…`, and JWKS at `{env}/keys` are easy to guess wrong. A guessed `{env}/resources/{res}/keys` is a 404.
- **A token for another MCP server in the same environment must fail.** Environment-root `iss` only proves "some resource in this Scalekit environment signed this." The per-server boundary is the resource id in `aud`.
- **Public MCP clients need Dynamic Client Registration (DCR) or a Client ID Metadata Document (CIMD).** Inspector, Claude, and Cursor will not start login if both are off.

## Who needs this

- You run an mcp-use v2 server over Streamable HTTP
- MCP clients must sign in before they call tools
- Tool data must be scoped to `ctx.auth.user.id`

Skip this recipe when you only need a shared machine credential and no user identity. For Scalekit M2M JWT verification on a regular API, see [M2M JWT verification with JWKS and OAuth scopes](/cookbooks/m2m-jwks-and-oauth-scopes/).

## The solution

Register the MCP server in Scalekit so Scalekit is the authorization server. Pass three values into the published factory: environment URL, resource id (`res_…`), and the public MCP URL. mcp-use returns **401** plus protected-resource metadata when a host has no token. The host discovers Scalekit, registers via DCR or CIMD, and retries with a bearer JWT.

The factory verifies signature, issuer, expiry, `sub`, and audience. Audience is the resource id. A Server URL may also appear in `aud`; it does not replace the resource-id check.

```ts
import { MCPServer } from "mcp-use";
import { oauthScalekitProvider } from "mcp-use/oauth/scalekit";

const server = new MCPServer({
  name: "my-mcp-app",
  version: "1.0.0",
  oauth: oauthScalekitProvider({
    environmentUrl: process.env.SCALEKIT_ENVIRONMENT_URL!,
    resourceId: process.env.SCALEKIT_RESOURCE_ID!,
    resource: process.env.MCP_URL!,
  }),
  publicLandingPage: true,
});
```

## Implementation

### 1. Register the MCP server in Scalekit

Scalekit becomes the authorization server. Your process only verifies the bearer token.

**Prerequisites:** Node.js 22.22.2 or newer, a [Scalekit account](https://app.scalekit.com), and at least one [auth method](/mcp/auth-methods/social/) enabled (Google, GitHub, passwordless, or [enterprise single sign-on (SSO)](/mcp/auth-methods/enterprise/)).

<Steps>

1. ### Add the MCP server

   Open [Scalekit Dashboard](https://app.scalekit.com) → **MCP servers** → **Add MCP server**. Give the server a name. That name appears on the consent screen.

2. ### Enable DCR and CIMD

   Turn on **dynamic client registration** and **Client ID Metadata Document (CIMD)**. Public MCP clients need at least one of these. Keep both on.

   Restart the mcp-use process after you change DCR or CIMD. Some MCP clients cache authorization-server metadata.

3. ### Set the Server URL with no trailing slash

   Under advanced settings, set **Server URL** to the canonical MCP endpoint:

   ```text
   http://localhost:3000/mcp
   ```

   A deployed origin `https://mcp.example.com` with the default `/mcp` base path uses `https://mcp.example.com/mcp`.

   Do not add a trailing slash. mcp-use strips it and requires the resource path to equal the server base path. An empty Server URL still works: Scalekit then mints tokens whose `aud` is only `res_…`. A filled Server URL sets `aud` to `[Server URL, res_…]`.

4. ### Copy the three values you will pass to the server

   Save the MCP server. Copy:

   | Value | Where it appears |
   | --- | --- |
   | Environment URL | Dashboard → API credentials → `https://<your-env>.scalekit.cloud` |
   | Resource ID | This MCP server page → `res_…` |
   | Public MCP URL | The same string as **Server URL** (no trailing slash) |

</Steps>

There is no client id or client secret on the resource server.

### 2. Install mcp-use and construct the provider

```bash
# Never hardcode secrets; use environment variables.
npm install mcp-use
```

```env
SCALEKIT_ENVIRONMENT_URL=https://your-env.scalekit.cloud
SCALEKIT_RESOURCE_ID=res_xxxxxxxx
MCP_URL=http://localhost:3000/mcp
```

The provider does not read those names on its own. Pass them in:

```ts
import { MCPServer } from "mcp-use";
import { oauthScalekitProvider } from "mcp-use/oauth/scalekit";

function requiredEnv(name: string): string {
  const value = process.env[name]?.trim();
  if (!value) {
    throw new TypeError(
      `${name} is missing. Copy .env.example to .env and fill in values from your Scalekit dashboard.`,
    );
  }
  return value;
}

const server = new MCPServer({
  name: "my-mcp-app",
  version: "1.0.0",
  oauth: oauthScalekitProvider({
    environmentUrl: requiredEnv("SCALEKIT_ENVIRONMENT_URL"),
    resourceId: requiredEnv("SCALEKIT_RESOURCE_ID"),
    resource: requiredEnv("MCP_URL"),
  }),
  publicLandingPage: true,
});

export default server;
```

| Check | What the provider verifies |
| --- | --- |
| Signature | JWKS at `{environmentUrl}/keys` (from live authorization-server metadata — not a guessed path) |
| `iss` | Environment root **or** `{environmentUrl}/resources/{resourceId}` |
| `aud` | Must include `resourceId` (`res_…`) |
| Identity | `ctx.auth.user.id` is the token `sub` |

`resourceId` is the per-server security boundary. A token minted for a different MCP server in the same Scalekit environment must fail.

Set `publicLandingPage: true` so the HTML landing page stays public while `/mcp` is bearer-gated.

### 3. Scope tool data to the signed-in user

Scalekit maps token `sub` to `ctx.auth.user.id`. `subjectType` is `user` for an authorization-code login and `machine` when `sub` equals the client id. Optional `org_id` and `sid` become `organizationId` and `sessionId`. OAuth grants are `ctx.auth.scopes`. Scalekit permissions are `ctx.auth.permissions`.

```ts
server.tool(
  {
    name: "whoami",
    description: "Return the authenticated Scalekit identity for this request",
  },
  async (_args, ctx) => {
    const data = {
      user: ctx.auth.user,
      scopes: ctx.auth.scopes,
      permissions: ctx.auth.permissions,
    };
    return {
      content: [{ type: "text", text: JSON.stringify(data, null, 2) }],
    };
  },
);

server.tool(
  {
    name: "list_documents",
    description: "List documents for the signed-in Scalekit user",
  },
  async (_args, ctx) => {
    if (ctx.auth.user.subjectType !== "user") {
      return {
        isError: true,
        content: [{ type: "text", text: "User access required" }],
      };
    }

    if (!ctx.auth.scopes.includes("documents:read")) {
      return {
        isError: true,
        content: [{ type: "text", text: "Missing scope documents:read" }],
      };
    }

    const documents = await db.documents.findMany({
      where: { ownerId: ctx.auth.user.id },
    });
    return {
      content: [{ type: "text", text: JSON.stringify(documents) }],
    };
  },
);
```

Authorization belongs next to the tool, not only at the HTTP gate. Do not store a `machine` `sub` as if it were a person.

## Testing

```bash
npm run dev
```

| Endpoint | URL |
| --- | --- |
| MCP | `http://localhost:3000/mcp` |
| Inspector | `http://localhost:3000/mcp/inspector` |

1. Unauthenticated `curl -i http://localhost:3000/mcp` returns **401** and a `WWW-Authenticate` header whose `resource_metadata` points at `/.well-known/oauth-protected-resource/mcp`.
2. That well-known document is public JSON. `authorization_servers` names the resource-scoped Scalekit issuer.
3. Open Inspector and connect to `http://localhost:3000/mcp`. The first call returns **401**; Inspector starts Scalekit login.
4. Complete consent. Call `whoami`.

Expected claim *shapes* (use your own environment — do not paste live ids):

```json
{
  "user": {
    "id": "usr_…",
    "subjectType": "user"
  },
  "iss": "https://your-env.scalekit.cloud",
  "aud": ["http://localhost:3000/mcp", "res_xxxxxxxx"]
}
```

`iss` may also be `https://your-env.scalekit.cloud/resources/res_xxxxxxxx`. The provider accepts both while Scalekit migrates issuer values.

A public URL change is two matching updates: Scalekit **Server URL** and `MCP_URL`. Restart the process. `resourceId` stays the audience check.

## Common mistakes

- **Trailing slash on Server URL or `MCP_URL`.** Symptom: login works, every tool is 401. Cause: the two strings do not match, or mcp-use rejected the trailing slash. Fix: use the full `/mcp` URL with no trailing slash on both sides.
- **DCR and CIMD both off.** Symptom: Inspector never starts login. Cause: public clients cannot register. Fix: enable both, then restart the mcp-use process.
- **Guessed JWKS path.** Symptom: every token is 401. Cause: `{env}/resources/{res}/keys` is a 404. Fix: use the published provider. It reads JWKS from `{environmentUrl}/keys`.
- **Audience set to the MCP URL only.** Symptom: tokens whose `aud` is `res_…` fail, or a token for another resource in the same environment is accepted. Cause: the security boundary is the resource id. Fix: pass `resourceId` and leave the default audience.
- **Import 404s on npm.** Symptom: `Cannot find module 'mcp-use/oauth/scalekit'`. Cause: the factory is not in the installed mcp-use release yet. Fix: wait for the release that includes [mcp-use#2272](https://github.com/mcp-use/mcp-use/pull/2272), or run the [example](https://github.com/scalekit-developers/scalekit-mcpuse-example) which still has the local verifier.

Set `MCP_USE_OAUTH_DEBUG=1` to print `iss`, `aud`, and `sub` on a 401. Logs never print the raw token.

## Production notes

- Restart after any DCR or CIMD change. Clients cache authorization-server metadata.
- `resourceId` is security-critical. A wrong `res_…` silently weakens the audience check instead of failing loudly. Copy it from the MCP server page.
- Do not set `issuerBoundAccessTokens: true`. A Scalekit issuer is a whole environment, so issuer-bound verification would accept a token minted for any other MCP server in that environment.
- Clock skew is not configurable in mcp-use today. Near-expiry 401s can be intermittent. Retry with a fresh token.
- Protected-resource metadata is served at `/.well-known/oauth-protected-resource/mcp` (path-suffixed). Hand-copying a dashboard URL that assumes the bare path points at a 404.
