Install `hermes-delegated-auth` so Hermes can act as a named user in GitHub, Gmail, Slack, and other apps. Scalekit stores the connected account. Hermes calls tools with the named user's token.

```d2
direction: right

Hermes: "Hermes Agent" {
  style.font-size: 18
}

Scalekit: {
  label: "Scalekit AgentKit"
  Auth: "OAuth handler"
  Vault: "Token vault"
}

Providers: {
  label: "Third-party services"
  Gmail: "Gmail"
  Slack: "Slack"
  Salesforce: "Salesforce"
  More: "200+ more"
}

Hermes -> Scalekit.Auth: "Execute tools"
Scalekit.Vault -> Providers.Gmail
Scalekit.Vault -> Providers.Slack
Scalekit.Vault -> Providers.Salesforce
Scalekit.Vault -> Providers.More
```

`hermes-delegated-auth` runs this loop when you name an app:

1. Looks up the Scalekit connection for [GitHub](/agentkit/connectors/github/), [Gmail](/agentkit/connectors/gmail/), or the app you named
2. Checks the named user's connected account. `ACTIVE` means Scalekit holds a working token
3. Returns a magic link if the connected account is not `ACTIVE`
4. Fetches the tool schema, calls the tool, and returns the result
5. Calls the Scalekit HTTP proxy if no named tool exists

A magic link is a one-time URL. The hosted page shows OAuth consent, or an API-key form.

## Prerequisites

- [Hermes Agent](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart) installed
- A Scalekit account with AgentKit enabled: [sign up at app.scalekit.com](https://app.scalekit.com)
- At least one connection in **Dashboard > AgentKit > Connections** (for example, GitHub)
- [`uv`](https://docs.astral.sh/uv/) on your `PATH`

## Install the skill on Hermes

<Steps>
1. ### Install hermes-delegated-auth

   Run this command:

   ```bash showLineNumbers=false
   hermes skills install scalekit-inc/authstack/kits/agentkit/host/hermes-delegated-auth
   ```

   Confirm the skill is enabled:

   ```bash showLineNumbers=false
   hermes skills list
   ```

   ```txt showLineNumbers=false
   │ hermes-delegated-auth │          │ local  │ local │ enabled │
   ```

   Install the Python dependencies:

   ```bash showLineNumbers=false
   cd "${HERMES_HOME:-$HOME/.hermes}/skills/hermes-delegated-auth"
   uv sync
   ```

   New chats load `/hermes-delegated-auth`. Run `/reset` in a chat that is already open.

   `HERMES_HOME` changes the skill path. The commands on this page use `~/.hermes`.

   Do not install from a raw `SKILL.md` URL. Hermes will miss `scripts/`.

   Do not install `integrate-agentkit-host`. `integrate-agentkit-host` is for coding agents, not Hermes.

2. ### Configure credentials

   Put only Scalekit client credentials in `~/.hermes/.env`. GitHub, Gmail, and Slack tokens never go in that file. Scalekit stores the provider tokens and refreshes them.

   ```bash title="~/.hermes/.env"
   SCALEKIT_CLIENT_ID=skc_your_client_id
   # Threat: a leaked secret lets anyone call tools as any ACTIVE identifier.
   SCALEKIT_CLIENT_SECRET=your_client_secret
   SCALEKIT_ENVIRONMENT_URL=https://your-env.scalekit.cloud
   SCALEKIT_IDENTIFIER=usr_8f3a2c
   ```

   | Parameter | Description |
   |-----------|-------------|
   | `SCALEKIT_CLIENT_ID` | Your Scalekit client ID <Badge text="Required" /> |
   | `SCALEKIT_CLIENT_SECRET` | Your Scalekit client secret <Badge text="Required" /> |
   | `SCALEKIT_ENVIRONMENT_URL` | Your Scalekit environment URL <Badge text="Required" /> |
   | `SCALEKIT_IDENTIFIER` | Named user this host acts as <Badge text="Required" /> |

   Copy the client ID, client secret, and environment URL from **Dashboard > Developers > Settings > API Credentials**.

   `SCALEKIT_IDENTIFIER` is not a dashboard credential. Pick an opaque id that only your system knows, for example `usr_8f3a2c`. Every `tool_exec.py` command needs `SCALEKIT_IDENTIFIER`, including `--list-connections`.

   Do not use an email, a first name, or another guessable string. `SCALEKIT_CLIENT_SECRET` lets anyone call tools as any `ACTIVE` identifier.

   In a multi-user product, add [user verification](/agentkit/user-verification/) so the wrong person cannot activate the slot.

3. ### Ask Hermes to act

   Start a chat and ask for a real action:

   <Tabs>
   <TabItem label="GitHub">
   ```txt showLineNumbers=false
   You: Who am I on GitHub?
   ```

   Hermes loads the skill and:

   1. Looks up the GitHub connection
   2. Checks that the connected account is `ACTIVE` (or gives you a magic link)
   3. Fetches the tool schema
   4. Calls the tool and returns the GitHub login
   </TabItem>
   <TabItem label="Gmail">
   ```txt showLineNumbers=false
   You: Show me my latest unread emails
   ```

   Hermes:

   1. Looks up the Gmail connection
   2. Gives you a magic link if you have not authorized yet
   3. Fetches the tool schema
   4. Returns the mail
   </TabItem>
   <TabItem label="Notion">
   ```txt showLineNumbers=false
   You: Read my Notion page https://notion.so/My-Page-abc123
   ```

   Hermes:

   1. Looks up the Notion connection
   2. Gives you a magic link if you have not authorized yet
   3. Fetches the page tool schema
   4. Returns the page content
   </TabItem>
   <TabItem label="Slack (as a user)">
   ```txt showLineNumbers=false
   You: As identifier usr_8f3a2c, list my unread Slack DMs
   ```

   Hermes:

   1. Looks up the Slack **user** connection
   2. Gives you a magic link if the Slack user account is not `ACTIVE`
   3. Fetches the Slack tool schema
   4. Returns the direct messages (DMs) as `usr_8f3a2c`, not as the Hermes bot
   </TabItem>
   <TabItem label="Google Calendar">
   ```txt showLineNumbers=false
   You: Create an out-of-office event tomorrow on the calendar for usr_8f3a2c
   ```

   Hermes:

   1. Looks up the Google Calendar connection for `usr_8f3a2c`
   2. Gives you a magic link if needed
   3. Calls the create-event tool
   4. Scalekit writes the event with the `usr_8f3a2c` token
   </TabItem>
   </Tabs>

   You can also force the skill:

   ```txt showLineNumbers=false
   /hermes-delegated-auth who am I on GitHub?
   ```

</Steps>

## Verify it works

Confirm all of the following:

- The skill is listed (`hermes skills list` or `/skills`) as `hermes-delegated-auth`
- The connected account is `ACTIVE` after you finish the magic link
- Hermes returns data from the provider (the GitHub login, or unread mail)

Open the magic link again and retry the same prompt if the account stays inactive.

## Use Slack as a bot or as a user

The Slack gateway and the Slack user connection are two identities. Do not mix them.

| Job | Use |
|-----|-----|
| Chat with the agent in a channel or DM | Hermes Slack **gateway**. Bot tokens (`xoxb-` + `xapp-`) in `~/.hermes/.env`. See the [Hermes Slack setup](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/slack). |
| Read private history, post, or act as a named person | Scalekit Slack **user** connection on that identifier |

The gateway bot is a channel. The gateway bot is not `usr_8f3a2c`.

Always-on hosts use both. The gateway hears the channel. Scalekit acts as the named user.

## Run jobs on a schedule

Attach the skill to a Hermes cron job. Each fire is a fresh session. The skill uses Scalekit client credentials. You do not mint a session token.

```bash showLineNumbers=false
hermes cron create "0 9 * * *" "List unread emails for usr_8f3a2c and post a 5-line summary" --skill hermes-delegated-auth
```

Or in chat:

```txt showLineNumbers=false
/cron add "every weekday at 9am" "List unread emails for usr_8f3a2c and post a 5-line summary" --skill hermes-delegated-auth
```

The connected account must already be `ACTIVE`. Cron cannot click a magic link.

Leave the gateway running on a headless host. A new magic link can then land in Slack or Telegram. Do not put Gmail or Calendar refresh tokens in `~/.hermes/.env`.

## Avoid these mistakes

- Do not put provider tokens in `~/.hermes/.env`. Put only Scalekit client credentials there.
- Do not set `SCALEKIT_IDENTIFIER` to an email or another guessable value.
- Do not use the bundled Google Workspace skill (`~/.hermes/google_token.json`) if AgentKit owns the Google user. `~/.hermes/google_token.json` is one laptop login, not a named identifier.
- Do not run `hermes mcp login` against Scalekit Virtual MCP (a Scalekit MCP URL plus a session token). Virtual MCP uses a static bearer session token. It is not MCP OAuth.
- Do not treat the Slack bot token as “send as usr_8f3a2c”.
- Do not use a Hermes host as a multi-tenant identity provider. One gateway is one operator. Switch identifiers on the same host. Do not mint per-customer session tokens inside Hermes.

## Fix common errors

<details>
<summary>How do I authorize a new connection?</summary>

The skill returns a magic link if the account is not `ACTIVE`. Open the link, finish the flow on the hosted page, then return to Hermes and retry.

The hosted page adapts to the connection. An OAuth connector asks for your consent. An API key connector, such as Snowflake, asks for the credential. Hermes never collects that credential in chat.

</details>

<details>
<summary>How do I switch users?</summary>

Set `SCALEKIT_IDENTIFIER` in `~/.hermes/.env` as the default.

Name the identifier in the prompt to act as someone else for one turn, for example `as identifier usr_8f3a2c`. Scalekit scopes tools to the named user's connected account.

</details>

<details>
<summary>Why do I see "connection not found"?</summary>

1. Confirm the connection exists in **Dashboard > AgentKit > Connections**
2. Confirm it is complete, not a draft
3. Confirm `SCALEKIT_ENVIRONMENT_URL` matches the environment that holds the connection

Use the connection `key_id` as the connection name, for example `github-connect`. Do not use the `conn_…` id.

</details>

<details>
<summary>The connected account is not ACTIVE</summary>

Check the state in **Dashboard > AgentKit > Connected accounts**:

| State | What you do |
|-------|-------------|
| `PENDING_AUTH` | Open the magic link and finish OAuth |
| `PENDING_VERIFICATION` | Complete [user verification](/agentkit/user-verification/) |
| `EXPIRED` | Open a new magic link. Scalekit cannot refresh a dead refresh token |
| `DISCONNECTED` | Reconnect from the Dashboard, then retry |

See [Manage connected accounts](/agentkit/connected-accounts/).

</details>

<details>
<summary>Should I use Virtual MCP instead?</summary>

No, not as the default. Hermes is a long-lived host. The skill calls `execute_tool` with client credentials. You do not mint a session token.

Virtual MCP is a Scalekit MCP URL plus a session token that your app mints. Hermes gateway and cron stay up for days. A bearer in `~/.hermes/.env` expires. There is no shipped remint hook.

Use Virtual MCP in your **app** for a short agent run (Claude Managed Agents, Mastra, CrewAI), or for a short `hermes chat` demo:

1. Create a Virtual MCP config in the Dashboard.
2. Mint a session token for one identifier.
3. Point Hermes at the static `mcp_server_url` with `Authorization: Bearer ${SCALEKIT_MCP_SESSION_TOKEN}`.
4. Start a new chat before the token expires.

Do not set `auth: oauth` on the Virtual MCP server.

</details>

<details>
<summary>Why does hermes mcp login fail against Scalekit?</summary>

`hermes mcp login` is for vendor MCP OAuth. Scalekit Virtual MCP is a static URL plus a session token that **your app** mints.

Use the `hermes-delegated-auth` skill, or set a bearer header as in [Set up a Virtual MCP server](/agentkit/mcp/configure-mcp-server/).

</details>

<details>
<summary>When do I not need Scalekit?</summary>

Skip Scalekit when no named user is involved:

- GitHub work through `gh` on the operator's own machine
- Your own Linear account through the connector Hermes ships (`hermes mcp install linear`)
- Slack used only as a chat channel, through the Hermes Slack gateway

Add Scalekit when Hermes must act as a specific person: read Gmail as `usr_8f3a2c`, post to Slack as that person, or write to that person's Google Calendar.

</details>
